## 8. Big O cheat sheet — complexity-sheet

Target: `https://algods.ru/big-o/`.

### Telegram
```text
Короткая памятка по сложности:
O(1) — постоянная работа, не обязательно одна инструкция.
O(log n) — пространство поиска сокращается в постоянное число раз.
O(n) — суммарно линейная работа, даже если в коде есть вложенный while.
O(n log n) — например, линейная обработка на логарифмическом числе уровней merge sort.
O(n²) — перебор пар.

Сначала определите n и стоимость одной операции. Big O не переводится напрямую в секунды.

В моём AlgoDS есть таблица времени/памяти и оговорки про expected/amortized/worst:
https://algods.ru/big-o/?utm_source=telegram&utm_medium=social&utm_campaign=algods_launch_2026_10&utm_content=complexity-sheet
```

### VK
```text
Два вложенных цикла не всегда означают O(n²). Если оба указателя двигаются только вперёд, суммарное число сдвигов может быть линейным. Но пересчёт всего окна внутри цикла снова добавит работу.

Чтобы оценить решение, определите размер входа, посчитайте все основные действия и отдельно память. Для хеш-таблиц различайте ожидаемую оценку и худший случай; для динамического массива — отдельную вставку и амортизированную стоимость.

Собрал памятку по Big O в своём бесплатном AlgoDS:
https://algods.ru/big-o/?utm_source=vk&utm_medium=social&utm_campaign=algods_launch_2026_10&utm_content=complexity-sheet
```

Изображение: верх таблицы `/big-o/` или `assets/complexity-work.svg`. Где: канал/сообщество с учебными материалами. Не писать «миллион операций всегда укладывается в секунду».
